# React + Flask + MySQL で REST API を作る実践教材

この教材で作るのは、**最初から最後まで REST API**です。画面（HTML）はサーバーでは作りません。

| 何を | この教材での選択 |
|---|---|
| バック | **Flask + SQLAlchemy** の、**JSON を返す REST API** |
| DB | **MySQL 8**（**Docker** で起動する。あなたのPCに直接 MySQL は入れない） |
| フロント | **React + TypeScript**（バックと完全に分離。API を `fetch` で叩く） |
| Python 環境 | **uv** で管理（`pip` や `venv` は使わない） |
| デバッグ | **iTerm2** でサーバーを起動しながら **Zed** でブレークポイントを張る |

> ⚠️ 念のため:
> **Jinja テンプレート（サーバーで HTML を組み立てる方式）も sqlite3（ファイル1個の簡易DB）も、この教材では使いません。**
> 画面は React、DB は Docker で立てた MySQL です。

---

## 題材について（なぜ Flaskr を下敷きにするか）

題材は Flask 公式チュートリアルの「**Flaskr**」というブログアプリ（ユーザー登録・ログイン・記事の投稿/編集/削除）です。
ただし**公式が使っている道具立て（Jinja + sqlite3）はそのまま使いません**。同じ「作るもの（ブログ）」を、実務で主流の **REST API + MySQL + Docker + React** に置き換えて作ります。

参照する元記事:
- [Flask 公式ドキュメント](https://flask.palletsprojects.com/)
- [Flask 公式チュートリアル（Flaskr）](https://flask.palletsprojects.com/en/3.0.x/tutorial/)

**置き換えの対応表**（公式の道具 → この教材の道具）:

| 公式チュートリアル（使わない） | この教材（こう作る） | なぜ置き換えるか |
|---|---|---|
| 生 `sqlite3` + `schema.sql` + `db.execute(...)` | **Flask-SQLAlchemy**（モデルクラス + `db.session`） | 実務では ORM が主流。型・リレーションが扱いやすくテストしやすい |
| `sqlite`（ファイル1個の簡易DB） | **MySQL 8 on Docker** | 実務で使う本格RDBを、PCを汚さず起動する練習をするため |
| `render_template()` + Jinja（サーバーでHTML生成） | **JSON を返す** → 画面は **React** が描く | フロント/バック分離の REST API 構成にするため |
| `flash()`（画面にメッセージ表示） | **JSON のエラーボディ** `{"error": "..."}` + HTTP ステータス | API はメッセージを JSON で返す |
| `redirect(url_for(...))` | **JSON + ステータスコード**（例 `201 Created`） | API はリダイレクトせず結果を返す |
| `request.form['username']` | **`request.get_json()`** | React は JSON ボディを送るため |
| `pip` + `venv` | **uv** | 依存解決が速く、`uv run` で仮想環境を意識せず実行できる |

本文中でも、公式から構成を変えた箇所には `🔁 置き換え`、公式に無い背景知識を足した箇所には `💡 補足` を付けます。

## 本文の読み方：2層構造

Python の文法を全部その場で解説すると、実装の流れが埋もれて頭が疲れます。それを防ぐため本文を2層に分けています。

| 層 | 名前 | 役割 | 見た目 |
|---|---|---|---|
| 主線 | 実装レイヤ | 「何を作るか」の手順。**ここだけ追えばアプリは動く** | 通常の本文 |
| 側線 | 言語仕様レイヤ | 「**なぜ**その文字列がそう動くか」の解剖 | `### 🔬 構文解剖` ブロック |

- Python の文法が既に分かる人は `🔬 構文解剖` を飛ばして主線だけ追えます
- 初めて出る記号・キーワードは、主線に登場する**直後**に必ず解剖します（説明なしでは絶対に出しません）
- 2回目以降に出る記法は再説明しません。「ステップ N の構文解剖参照」と誘導します

### 各ステップに必ず付くマーク

| マーク | 意味 |
|---|---|
| 🔴 **毎日書く** / 🟡 **読めればよい** / ⚪ **背景知識** | そのステップの実務での重要度 |
| 🔬 **構文解剖** | 記号・キーワードを1行ずつ分解 |
| 🏢 **実務メモ** | 現場でどう書くか / なぜそう書くか |
| ⚠️ **やりがち** | アンチパターンと現場での回避法 |
| 🔮 **実行前に予想** | 動かす前に結果を予想する（記憶に残すため） |
| ✅ **想起チェック** | 見ないで説明できるか、の小問（答えは折りたたみ） |
| ✍️ **ブランクページ** | 章末。ファイルを閉じて白紙から再現する |
| 🔁 **置き換え** | 公式チュートリアル（Flaskr）から構成を変えた箇所 |
| 💡 **補足** | 公式に無い、筆者が足した背景知識 |

## この教材で作る完成物（REST API）

React フロントが叩ける、次の JSON API を Flask で作ります。

| メソッド | パス | 説明 | 認証 | 返すもの |
|---|---|---|---|---|
| `POST` | `/auth/register` | ユーザー登録 | 不要 | 作成したユーザーの JSON |
| `POST` | `/auth/login` | ログイン（セッション Cookie 発行） | 不要 | ユーザーの JSON |
| `POST` | `/auth/logout` | ログアウト | 不要 | `204 No Content` |
| `GET`  | `/auth/me` | ログイン中のユーザー情報 | 任意 | ユーザー or `null` |
| `GET`  | `/posts` | 記事一覧（新しい順） | 不要 | 記事の JSON 配列 |
| `POST` | `/posts` | 記事作成 | 必須 | 作成した記事（`201`） |
| `GET`  | `/posts/<id>` | 記事1件 | 不要 | 記事の JSON |
| `PUT`  | `/posts/<id>` | 記事更新（著者本人のみ） | 必須 | 更新後の記事 |
| `DELETE` | `/posts/<id>` | 記事削除（著者本人のみ） | 必須 | `204 No Content` |

DB は Docker で立てた **MySQL** に保存します。画面は React + TypeScript から上記 API を `fetch` して描きます。
